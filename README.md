# ONYX — нейро-символічна платформа кіберрозвідки

Система збирає відкриті джерела з кібербезпеки (Telegram-канали, YouTube,
сайти та RSS), видобуває з постів події (вразливості, техніки атак), звіряє їх
із довідниками NVD та MITRE ATT&CK і складає в пошуковий індекс. Поверх індексу
працює аналітичний інтерфейс: гібридний пошук, рада ШІ-агентів із синтезатором,
семантична мережа понять, граф гіпотез і сценарії на орієнтованому графі.

Дипломний проєкт. Кафедра інформаційної безпеки.

---

## Архітектура

```
 колектори ──► MongoDB ──► shipper ──► Manticore ──► ONYX UI
 Telegram      raw_events   ембединг    events_enriched  Streamlit
 YouTube       (джерело     дедуп       FTS + KNN 768d   стрічка / чат /
 сайти, RSS    правди)      екстракція  content: indexed сценарії
                  ▲         заземлення  БЕЗ stored           │
                  │         верифікація                      │
                  └──────── повний оригінал тексту за mongo_id ┘
```

Система свідомо розведена на два сховища з різними ролями:

- **MongoDB — джерело правди.** У `raw_events` лежить сирий текст як він
  прийшов. Обробку можна повторити з новою моделлю чи промптом, не втративши
  оригінали.
- **Manticore — пошуковий індекс.** Поле `content` оголошене як `TEXT indexed`
  без `stored`: тіло документа індексується для повнотекстового пошуку, але не
  зберігається. Тому будь-який показ документа — це два кроки: знайти в
  Manticore, дотягнути оригінал із Mongo за `mongo_id`.

Інференс теж розведений: ембедер `nomic-embed-text` лишається локальним в Ollama
(легкий, працює на CPU; його заміна знецінила б уже проіндексовані вектори),
а важка LLM (Hermes 3) винесена за OpenAI-сумісний HTTP — у хмару (OpenRouter)
або в локальну Ollama через `/v1`.

Зв'язок між шарами — MongoDB Change Stream: shipper слухає вставки в
`raw_events`, а resume-токен комітить у саму Mongo, тож після рестарту продовжує
з місця падіння.

## Стадія збагачення

`shipper/pipeline.py` — сім кроків, три виходи (докладніше в
[shipper/README.md](shipper/README.md)):

1. гейт порожнього тексту (медіа без підпису → `skipped`);
2. ембединг — `nomic-embed-text`, 768 вимірів, L2-норма;
3. видобування сутностей — LLM, `temperature 0`, строгий JSON; текст документа
   передається як недовірений у делімітерах (`prompt_guard.py`);
4. заземлення міток (`shipper/grounding.py`) — CVE/техніка приймається лише
   якщо ідентифікатор є в тексті дослівно або модель навела цитату, яка справді
   міститься в документі;
5. символьна верифікація — NVD 2.0 для CVE, STIX-бандл MITRE для технік
   (відкликані та застарілі відкидаються); статуси `verified / not_found /
   invalid_format / unreachable`;
6. семантичний дедуп — cos ≥ 0.92 у вікні з 1000 останніх векторів
   (перефразований репост → `duplicate`);
7. `EnrichedDocument` → черга → `/bulk` батчами по 50 документів або 2 с;
   у `content` лягає **лематизований** текст.

Результат моделі не потрапляє в індекс, доки кожен CVE і кожна техніка не
звірені із зовнішнім довідником. Саме цей стик нейронного й символьного шарів
робить платформу нейро-символічною, а не «обгорткою над LLM». Лічильники
`cve_count_verified` / `ttp_count_verified` потім стають якорями в графі гіпотез.

## Три тири дедуплікації

Один і той самий інцидент приходить із десятка каналів: спершу дослівним
репостом, потім переказом. Тири розставлені за зростанням ціни перевірки:

| Тир | Де | Механізм | Що ловить |
|---|---|---|---|
| 1 | Mongo, до всього | унікальний індекс `(channel_id, message_id)` | повторний збір того самого повідомлення |
| 2 | Mongo, до ембедингу | унікальний індекс `content_hash` (sha256) | дослівний репост з іншого каналу |
| 3 | shipper, після вектора | cos ≥ 0.92, вікно 1000 векторів | переказ своїми словами, переклад |

Перші два тири — partial-індекси в Mongo (`collector_dedup.py`), вони
спрацьовують ще до того, як подія дійде до shipper, і коштують нуль.

## Гібридний пошук

Три незалежні стратегії, зведені круговим обходом (`retrieval.py`,
`ui.py: retrieve_context()`):

- **fts_uk** — OR-матчинг у `content` після лематизації запиту (`pymorphy3`);
  Manticore не має власного стемера для української, тому морфологія зводиться
  зовні, симетрично на індексі й на запиті (`lemmatizer.py`);
- **fts_en** — переклад запиту англійською (LLM) та OR-матчинг у `title + summary`
  зі `stem_en`;
- **knn** — HNSW за косинусом, відсів за `dist ≥ 0.30`.

`merge_hits` бере по одному документу з кожної черги → 8 документів у контекст.
Жодна стратегія не з'їдає ліміт цілком.

## Рада агентів

Знайдені документи не йдуть у модель як є: кожен обгортається делімітерами
`<<<UNTRUSTED_DOCUMENT` і нумерується — захист від непрямої ін'єкції промпту
(OSINT-текст пише хто завгодно). До 5 агентів працюють над одним набором
джерел і відрізняються лише системними промптами (шаблони: CTI-аналітик,
прогнозист загроз, MITRE-тактик, IOC-екстрактор, Red Team); кожному агенту можна
задати окремий LLM-бекенд (`llm_backends.py`). Синтезатор вмикається лише коли
агентів більше одного і бачить не корпус, а відповіді агентів. «Колбаса»
(`rag_context.py`) показує людині рівно ту вибірку, що пішла в модель.

## Семантична мережа й гіпотези

`semantic_reasoner.py`. Ланцюги міркування не генеруються моделлю — вони
видобуваються з графа, побудованого на реальному корпусі, а модель лише
інтерпретує знайдене.

- вузли — терміни від 4 символів із заголовка й реферату (≤ 40 на документ) плюс
  верифіковані CVE та техніки MITRE як **якорі** (boost ×2);
- вага ребра — нормалізована поточкова взаємна інформація (NPMI) у
  діапазоні [−1, 1]: гасить вузли-хаби, які трапляються всюди;
- вартість = 1 / вага; `single_source_dijkstra` **від цілі назад**, шляхи
  розвертаються старт → … → ціль;
- ранжування за середньою вагою ребра, а не сумою вартостей (інакше сильний
  трихоповий ланцюг тонув під слабшим однохоповим); 5 гіпотез до 6 хопів.

Поруч — семантична мережа понять за методологією Ланде (топ-40 термінів, ребра
за співпоявою з порогом, експорт у GraphML/GEXF).

## Сценарії на орієнтованому графі

`twin_scenarios.py` + `twin_bridge.py` + `qa/twin.py`. Співпоява понять дає
неорієнтований граф і не виражає причинності. Для сценаріїв атаки будується
типізований орієнтований граф (стани, вразливості, контролі, AND/OR-гейти),
з нього перебираються допустимі шляхи S0 → ST і ранжуються за інтегральною
оцінкою J.

Контекст пошуку звужується двостороннім розширенням: пряме від S0, зворотне від
ST, далі перетин. На 100 корпоративних мережах це прибирає 80,8 % вузлів,
причому перетин лишає на 37 % менше вузлів, ніж саме лише пряме розширення.
Звуження не евристичне — вузол справжнього шляху належить обом розширенням за
побудовою, тому розв'язок відрізати неможливо: на мережах, де завершились обидві
конфігурації, знайдено рівно ті самі шляхи (коефіцієнт Жаккара 1,0). Ціна —
виключно у здійсненності: без узгодження 19 мереж зі 100 не вкладаються в
десятисекундний бюджет.

## Синтез захисту

`twin_defense.py`. Знайдені шляхи компрометації задають зворотну задачу: яким
набором заходів їх розірвати. Це задача про мінімальну трансверсаль — шукаються
мінімальні за включенням набори, що розривають усі подані шляхи.

Розривають шлях лише ребра `mitigates`. `detects` і `recovers_from` реагують
після того, як перехід уже стався: зменшують наслідок, а не ймовірність.

Покриття й допустимість перевіряються окремо. Набір, що розриває все, але не
влазить у бюджет, показується з позначкою, а не зникає мовчки. Окремо
розрізняються порушена вимога й вимога, яку **неможливо оцінити** за наявними
даними: брак поля не є доведеною невідповідністю.

## Двостороння семантична мережа: від проблеми до розв'язку

`semantic_bridge.py` + `network_context.py` + `solution_survey.py`, стенд —
`scenario_lab.py`. Інша постановка, ніж у сценаріях атаки: задача не шукати
шляхи компрометації, а будувати мережу понять від **проблеми** (слабка
захищеність конкретної мережі) до **розв'язку** (бажаний стан) і знаходити
ланцюги між ними.

1. Фізична мережа (XML із `experiments/corporate_networks/dataset`) іде в
   промпти лише як контекст: вузли, сегменти, вимкнені й часткові засоби
   захисту, повторні паролі, обмеження. Розділ `<attacks>` не використовується.
2. Мережа росте з двох фронтів: прямий — від проблеми («що з цього випливає»),
   зворотний — від розв'язку («що має бути зроблено перед цим»). Кожне
   розкриття — виклик мовної моделі; корпус (RAG) — необов'язкова опора.
3. Мости між фронтами: ембединги відбирають найближчі пари, модель одним
   пакетним викликом підтверджує, які справді ведуть одна до одної. Кожен міст
   дає ланцюг «проблема → … → міст → … → розв'язок».
4. Кроки оцінює модель (ціна, час, вплив, 1-5), ланцюги ранжуються за J
   (`qa.twin.aggregate`).
5. Легенда простою мовою для кожного варіанта й анкета «як розв'язати
   проблему?»: респондент обирає найкращий варіант за часом, ціною й впливом.
   ШІ-експерти Л1–Л3 відповідають на ту саму анкету — незалежно, без балів
   розрахунку, у власному порядку варіантів, з обґрунтуванням на кожне питання;
   другий раунд — метод Дельфі (анонімні відповіді інших, можна змінити думку).

Підводні камені, на які наткнулись при перевірці на живій моделі:
`nomic-embed-text` не розрізняє зміст українських фраз, тож поняття
порівнюються за англійською формою, яку модель дає разом з українською;
навіть англійською різні дії над тими самими вузлами близькі (≈0.93), тому
автоматично приймається лише майже тотожність (≥0.96), решту підтверджує
модель; перевірка мостів і оцінки йдуть з температурою 0 — інакше той самий
граф давав то нуль, то шість мостів.

Запуск стенда (потрібні лише OpenAI-сумісна LLM і ембедер, напр. LM Studio):
`streamlit run scenario_lab.py`. Побудовані мережі кешуються в
`data/semantic_cache/`, відповіді анкет — у `data/surveys/`.

## Автентифікація UI

`auth/`: argon2id для паролів, експоненційне блокування після невдалих спроб,
однакова відповідь на «невірний пароль» і «немає такого логіна», довірені
пристрої з опаковими токенами (у базі — лише sha256-відбиток). Самореєстрації
немає навмисно; облікові записи заводить адміністратор (`tools/create_user.py`).

## Швидкий старт (локально)

Потрібні **Python 3.11+** і **Docker**. Mongo, Manticore та Ollama у систему не
ставляться — вони живуть у контейнерах.

### 1. Конфігурація

```bash
cp .env.example .env
```

У `.env`: `API_ID` / `API_HASH` (my.telegram.org → API development tools),
`LLM_API_KEY` (OpenRouter) або локальний блок Ollama, за бажанням `NVD_API_KEY`.
Кожна змінна пояснена в самому шаблоні. `.env` у `.gitignore`.

### 2. Стек

```bash
docker compose up -d
docker compose exec ollama ollama pull nomic-embed-text   # ембедер
docker compose exec ollama ollama pull hermes3            # лише для локальної LLM
docker compose logs -f shipper
```

Replica set `rs0` ініціюється автоматично healthcheck-ом контейнера Mongo.
На Windows усе це робить `start_docker.bat`.

### 3. Колектори

```bash
pip install -r requirements-collectors.txt
python tg.py                  # живий збір; перший запуск — авторизація Telegram
python migrate_history.py     # історія каналів
python collect.py all         # YouTube + сайти/RSS (джерела — у channels.json)
```

Джерела задаються в `channels.json`:

```json
{
  "channels": ["https://t.me/..."],
  "youtube":  ["https://www.youtube.com/@somechannel", "https://youtu.be/VIDEO_ID"],
  "websites": ["https://feeds.feedburner.com/TheHackersNews", "https://example.com/article"]
}
```

### 4. Інтерфейс

```bash
pip install -r requirements-ui.txt
python tools/create_user.py add <login>     # пароль спитає інтерактивно
streamlit run ui.py
```

Інтерфейс відкривається на http://localhost:8501 і вимагає входу.

### Перевірка

```bash
docker exec -it <mongo-контейнер> mongosh
```

```javascript
use threat_intel
db.raw_events.countDocuments({})
```

У логах shipper для кожної події має бути `pipeline_success`, `pipeline_duplicate`
або `pipeline_skipped_empty_text`.

## Сервер

Стек живе в контейнерах: Mongo, Manticore, Ollama, shipper; Streamlit слухає
`127.0.0.1:8501` і публікується назовні зворотним проксі. Mongo працює з
`--auth`, порти сервісів не світяться в мережу.

На поточному боксі є GPU, тож `hermes3` крутиться локально в Ollama, а не тільки
за хмарним OpenAI-сумісним API. Ембедер лишається там само.

> [DEPLOY_SERVER.md](DEPLOY_SERVER.md) описує ранішу конфігурацію — спільний бокс
> без GPU з доступом до UI через SSH-тунель. Покрокові команди звідти лишаються
> чинними, але припущення про відсутність GPU і про сусідів по машині вже ні.

## Тести

```bash
pip install pytest pytest-asyncio
pytest tests/
```

Тести не потребують мережі, LLM чи запущених сервісів — залежності замінені
на заглушки. Частина файлів запускається і напряму (`python tests/test_*.py`).

## Експерименти

Усі прогони детерміновані й не потребують ні мережі, ні LLM — окрім оцінювача
критеріїв, який звертається до моделі за побудовою.

**`experiments/htb_reconstruction/`** — чи відновлює обхід графа відомий ланцюг
атаки на моделях навчальних машин Hack The Box.

```bash
python experiments/htb_reconstruction/run_experiment.py --split demo --check-determinism
python experiments/htb_reconstruction/build_atlas.py
```

**`experiments/corporate_networks/`** — 100 згенерованих корпоративних мереж із
прихованим еталоном. Еталон перевіряється, а не приймається на віру: добуток
експлуатованості кроків, обчислений із публічної частини опису, збігається із
записаною ефективністю для всіх 500 атак із точністю 1e-6.

Чотири вимірювання: реконструкція шляху, згода ранжування окремо від пошуку,
синтез захисту, і базова лінія — неорієнтована проєкція **того самого** графа.

```bash
python experiments/corporate_networks/run_experiment.py --check-determinism
python tools/run_reconcile_ablation.py      # внесок двостороннього звуження
```

**`experiments/corporate_12node/`** — прогін оцінювача критеріїв на моделі
корпоративної мережі з 12 активів (`qa/fixtures/corporate_12node.yaml`), по три
повтори при двох температурах. Потребує доступу до LLM.

```bash
python tools/run_12node_eval.py
```

## Параметри, які визначають поведінку

| Параметр | Значення | Що визначає |
|---|---|---|
| Ембедер | `nomic-embed-text`, 768d | локально в Ollama; зміна моделі знецінює проіндексовані вектори |
| LLM | Hermes 3 | OpenAI-сумісний HTTP; екстракція, переклад, синтез |
| Поріг дублю | cos ≥ 0.92 | вище — пропускає перекази; нижче — з'їдає різні інциденти |
| Вікно дедупу | 1000 векторів | компроміс між пам'яттю і глибиною порівняння |
| Мікробатч | 50 док. / 2 с | що настане раніше — те й запускає запис у Manticore |
| Відсів KNN | dist < 0.30 | без нього вектор завжди повертає «щось», навіть нерелевантне |
| Контекст чату | 8 документів | ліміт після злиття трьох стратегій |
| Морфологія індексу | `stem_en, stem_ru`, `min_infix_len=3`, `index_exact_words=1` | словоформи на індексації й на запиті |
| Українська морфологія | `pymorphy3` | зовнішня лематизація, симетрично на індексі й запиті |
| Термінів на документ | ≤ 40 | стеля в графі міркувань, щоб хаби не роздували мережу |
| Гіпотез на запит | 5, до 6 хопів | ранг за середньою вагою ребра ланцюга |
| Заземлення міток | `literal` | мітка без дослівного ID у тексті не проходить |

Корпус — багатомовний (українська, англійська, російськомовні OSINT-джерела),
тому стоп-слова, стемери індексу та розпізнавання намірів покривають усі три мови.
